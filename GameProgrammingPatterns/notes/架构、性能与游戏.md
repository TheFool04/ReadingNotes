> 游戏程序架构不是为了“看起来高级”，而是为了在灵活性、性能、迭代速度之间做权衡。
> 模式不是越多越好，抽象不是越多越好，解耦不是越彻底越好。
> 因为过度的设计会导致可维护性差、运行时性能降低。

---

# 一、要点

## 1.1 好的架构服务于“变化”

> 当你要改一个功能时，感觉代码就是为了这次改动而设计的。

|     需求变化     |              架构差的表现               |           架构好的表现           |
| :--------------: | :-------------------------------------: | :------------------------------: |
| 技能加一个新效果 | 改技能类、角色类、动画类、UI 类、音效类 |     只新增一个效果模块或配置     |
| UI 新增红点规则  |               到处塞 `if`               | 红点系统独立计算，业务只提供数据 |
| 相机跟随策略调整 |        输入、角色、相机互相引用         |      相机系统只消费目标状态      |
| 战斗结算规则变化 |         表现层和逻辑层混在一起          |     战斗逻辑可独立修改和测试     |
| 新增怪物 AI 状态 |         `Update()` 里继续堆条件         |      状态机或行为结构可扩展      |

在设计前要问：

`这段代码未来最可能怎么变？现在的组织方式能不能承受这种变化？`

---

## 1.2 解耦的本质是降低脑内负担

> 软件架构的核心目标，是将你在取得进展之前需要在颅内保有的知识量降到最低。

解耦不是为了形式上的“模块化”，而是为了让你能够只理解一部分代码，就能安全地修改它。

很多人理解解耦时会停留在：

- 类不要互相引用
- 多用接口
- 模块之间通过事件通信

这只是手段，不是目的。

真正的问题是：

`当我改 A 的时候，是否必须理解 B、C、D、E？`

如果只需要理解 A，那么这就是“降低脑内负担”。所以在解耦时，要使用以下标准判断：

`这个模式到底减少了我需要同时理解的东西，还是只是制造了更多抽象层？`

---

## 1.3 抽象是有成本的

> 不要为“想象中的未来需求”设计复杂架构；只为“已经出现或高度确定会出现的变化”设计结构。

每增加一层抽象，都是在猜测未来会需要这种灵活性。如果猜错了，这些抽象不会带来收益，反而会变成你必须维护的复杂度。所以有一种设计模式叫 $YAGNI$：
$$
You \space Aren't \space Gonna \space Need \space It：你不会需要它
$$

---

## 1.4 性能优化依赖“假设”，架构灵活性则试图减少“假设”

> 架构往往是为了灵活：少写死假设，多留扩展空间。但性能优化恰恰依赖具体假设。
> 架构是在推迟假设；优化是在锁定假设。

| 性能优化           | 背后的假设         |
| :----------------- | :----------------- |
| 用数组而不是链表   | 数据连续访问更快   |
| 用对象池           | 对象频繁创建销毁   |
| 用 byte 存 ID      | 数量不会超过 255   |
| 静态分发 / 内联    | 调用目标类型固定   |
| ECS / SoA 数据布局 | 大量同类对象批处理 |
| 减少虚函数         | 不需要运行时多态   |

---

## 1.5 原型代码可以烂，但必须真的能扔

本章有一个很现实的观点：潦草代码不是绝对错误。游戏开发早期需要快速试验玩法，很多代码本来就是为了回答一个问题：

> “这个玩法好不好玩？”

如果只是验证玩法，写得太优雅反而会浪费时间。作者说，原型开发是合理的，但前提是：如果你打算写可丢弃代码，就必须确保它真的会被丢弃。一种方式是：原型代码用另一种语言写，这就保证写入项目的代码必然会进行一次重构

---

## 1.6 简洁不是少写代码，而是蒸馏问题

==真正高级的代码不是抽象层多，而是数据结构和算法刚好表达问题本质。==



# 二、架构设计模板

游戏客户端中的架构设计，本质上是在判断：

> 哪些代码会频繁变化，哪些代码需要高性能，哪些代码只是为了快速验证玩法

在设计架构前，先问自己以下问题：
- 哪些地方会频繁改变？
- 哪些地方不太会变？
- 我是在做原型还是正式系统？
- 这层抽象能否减轻理解负担？
- 这个地方是不是性能热点？
- 这个系统是否需要支持设计师快速迭代？
